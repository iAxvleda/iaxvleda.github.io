## Make performance an engineering constraint

A performance budget defines the response time, throughput, or resource envelope a critical journey must stay inside. It turns a vague aspiration into a signal that can be tracked.

## A lightweight approach

1. Select a few journeys that represent real user or system pressure.
2. Record a repeatable baseline in a controlled environment.
3. Define a budget around the experience the product needs.
4. Run a small comparison on relevant changes.
5. Investigate trends before they become release-blocking regressions.

Large load tests still have a place. A small, frequent budget catches everyday degradation much earlier.
